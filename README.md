# 科贸小鱼 · 校园集市小程序

> 广东科贸职业学院（清远校区）的校园闲置交易与生活服务平台。
> 微信小程序 + 云开发（云函数 / 云数据库 / 云存储），从设计、开发到部署全流程完成。

---

## 1. 项目介绍

校园里的二手交易、代拿快递、拼团、租借需求真实存在，但现有渠道要么散落在微信群（信息一刷就没、无法检索），要么依赖闲鱼这类平台（对同校面交、代跑腿这种场景太重）。

科贸小鱼把**商品交易、代跑腿、拼团、租借、换物、校园墙、学习资料**收在一个小程序里，并用 AI 解决三个最费人力的问题：

| AI 能力 | 解决什么 | 实现方式 |
|---|---|---|
| 发布助手 | 只写「出个显示器 200」，自动补标题、描述、分区、标签 | 云函数 + LLM，fail-soft，模型不可用时退回规则 |
| 语义搜索 | 「有没有便宜的台灯」也能搜到「护眼灯 30 出」 | 召回候选 + 模型重排，返回 id 必须来自真实召回（防幻觉） |
| 内容审核 | 发布/评论前自动拦截违规文本 | 规则 + 模型双判，取更严的一方 |

此外内置：站内私信（WebSocket 实时）、订单与担保交易状态机、收藏关注、举报处理、管理后台。

## 2. 技术架构

### 2.1 整体架构

```
┌──────────────────────────────┐
│        微信小程序（原生）        │   29 个页面 / 5 个组件
│  页面层 → 组件层 → utils/api.js │   token 持久化、统一错误提示、云调用封装
└───────────────┬──────────────┘
                │ wx.cloud.callFunction({ name:'campus', data:{path,method,data,token,scope} })
┌───────────────▼──────────────┐
│      云函数 campus（单函数多路由）   │
│  index.js   路由匹配 / 作用域 / 签名  │
│  route-*.js 业务路由（core/trade/…） │
│  db.js      数据层（内存镜像 + 云库） │
│  auth.js    登录态 / 权限            │
│  ai.js      发布助手 / 语义搜索 / 审核 │
│  sign.js    私有存储图片签名          │
└──────┬──────────────┬────────┘
       │              │
┌──────▼──────┐ ┌─────▼──────┐
│ 云数据库      │ │ 云存储（私有桶）│   24 个集合
│ 文档型        │ │ 图片 / 头像    │
└─────────────┘ └────────────┘

┌──────────────────────────────┐
│  本地管理后台（Node 原生 http）      │  独立 3100 端口，小程序内无入口
│  server/public/index.html    │  单页 + 原生 JS，零第三方框架
│  数据源：本地演示库 / 透传云函数      │  填 API Key 即切换为线上真实数据
└──────────────────────────────┘
```

### 2.2 关键设计

| 设计 | 说明 |
|---|---|
| 单云函数多路由 | 一个 `campus` 函数承载全部接口，避免多函数冷启动与部署成本；路由按业务拆文件 |
| 数据层双写 | 内存镜像加速读、云库为准（`readAllFromDb` 兜底），解决多实例快照不一致 |
| 图片签名 | 存储桶私有且免费版无法改权限 → 云函数 `getTempFileURL` 签发临时链接，前端零改动 |
| 作用域隔离 | `scope=api`（小程序）与 `scope=admin`（后台）走不同路由表，互不可见 |
| 失败降级 | AI、签名、通知全部 fail-soft，任一外部依赖挂掉不影响主流程 |

## 3. 功能概览

**用户端（29 个页面 / 5 个组件）**

- 首页：九大分区、搜索、AI 推荐、公告弹窗
- 商品：发布（AI 补全 + 多图上传）、筛选、详情、收藏、拍下即锁
- 交易：下单、支付状态、发货收货、评价、订单列表
- 社区：校园圈子（发帖 / 评论 / **评论配图 ≤3 张** / 点赞）、校园墙（匿名）、学习资料
- 拼团：开团、参团、我的拼团
- 私信：一对一实时聊天、未读、已读回执、AI 客服
- 我的：主页、我的动态、订单、钱包、地址、设置、实名

**管理后台（本地 Web，端口 3100）**

仪表盘、商品、用户（封禁/解封）、订单、举报、圈子、**评论管理**、校园墙、学习资源、拼团、公告、系统设置。

## 5. 安装运行指南

### 5.1 环境要求

- Node.js ≥ 18（推荐 20 / 22）
- 微信开发者工具（稳定版即可）
- 无需自建数据库或服务器：全部使用微信云开发

### 5.2 依赖清单

| 依赖 | 版本 | 用途 | 安装位置 |
|---|---|---|---|
| `wx-server-sdk` | `~4.0.2` | 云函数调用云数据库 / 云存储 | `cloudfunctions/campus/package.json`（云端安装） |
| `ws` | `^8.22.0` | 本地后台 WebSocket 实时推送 | 根 `package.json` |
| `busboy` | `^1.6.0` | 本地后台表单 / 文件上传解析 | 根 `package.json` |

本地后台刻意保持零第三方框架（只用 Node 内置 http / https），依赖仅上述两个。

```bash
npm install          # 安装 ws / busboy（首次必须，否则后台起不来）
```

### 5.3 小程序

1. 微信开发者工具 →「导入项目」→ 选择**本仓库根目录**
2. 需要是该小程序（AppID 见 `project.config.json`）的**项目成员**
3. 云环境 ID 在 `miniprogram/utils/config.js`
4. 编译即可运行

### 5.4 云函数部署

开发者工具中右键 `cloudfunctions/campus` →「上传并部署：云端安装依赖」。
CLI 方式与常见报错见 `DEPLOY.md`。

首次部署后冷启动会自动建集合并写入演示数据。

### 5.5 本地管理后台

```bash
node tools/start-admin.js        # 或 Windows 双击 start-admin.cmd
```

打开 `http://127.0.0.1:3100`，默认账号 **admin / admin**（登录后到「系统设置」修改）。
同一 WiFi 下可用启动日志打印的 `http://<内网IP>:3100` 访问。

## 6. 环境配置说明

所有配置通过**环境变量**注入，模板见 [`.env.example`](./.env.example)。

| 变量 | 默认值 | 必填 | 说明 |
|---|---|---|---|
| `API_PORT` | `3000` | 否 | 本地 API 端口（开发者工具模拟器用） |
| `API_HOST` | `127.0.0.1` | 否 | 本地 API 监听地址 |
| `ADMIN_PORT` | `3100` | 否 | 管理后台端口 |
| `ADMIN_HOST` | `0.0.0.0` | 否 | 管理后台监听地址；设 `127.0.0.1` 仅本机可访问 |
| `CLOUDBASE_ENV_ID` | 见 `server/src/cloud.js` | 否 | 云开发环境 ID |
| `CLOUDBASE_API_KEY` | 空 | 否 | 填了后台读**线上真实数据**；不填用本地演示库 |
| `LLM_API_KEY` | 空 | 否 | AI 能力；未配置时自动降级，功能不报错 |
| `LLM_BASE_URL` / `LLM_MODEL` | 见 `ai.js` | 否 | 兼容 OpenAI 协议的任意服务 |

> 凭据文件 `server/.cloudbase.json` 已被 `.gitignore` 排除，**不会**进入仓库。
> 需要接线上数据时：复制 `server/.cloudbase.json.example` 并填入自己的 Key。
> 云函数侧的 AI Key 配在云开发控制台「云函数 → 配置 → 环境变量」，不要写进代码。
